# 路2：用腳本排程 — 各平台設定與注意事項

> **結論先說**：最穩定的做法是 **Mac launchd**（每天固定時間自動跑，不需要電腦睡著前有人手動觸發）。若希望完全雲端、不依賴本機，可用 **GitHub Actions**，但存檔需要另外設定 Drive API。Codex Automations 和 Claude Routines 各有明確限制，選之前先看本頁的對照表。

---

## 一、能力需求表

在選擇排程平台之前，先確認 `digest.py` 需要哪些能力：

| 能力 | 說明 | 備註 |
|------|------|------|
| **定時排程** | 每天固定時間自動執行（例如每天 08:00） | 必要 |
| **可對外發出 POST 請求** | 呼叫 `eutils.ncbi.nlm.nih.gov`（PubMed API）與 `api.line.me`（LINE Messaging API push） | 必要；部分平台預設封鎖 POST |
| **跨次持久存檔** | 記住「今天送過哪些論文」以避免重複推送，需要寫入固定路徑的檔案或資料庫 | 必要 |
| **執行 LLM（選配）** | 用 Claude / Gemini 等產生中文摘要 | 選配；本機執行需有 API 金鑰 |

---

## 二、Mac launchd（最推薦）

### 適用情境
- 電腦主要時間是開著的（例如辦公室、家裡的 Mac）
- 不想依賴任何雲端帳號
- 檔案存在本機或 Google Drive 桌面同步資料夾

### 設定步驟

#### 第一步：建立 `.plist` 設定檔

把下方內容複製，儲存為一個新檔案，路徑放在：

```
~/Library/LaunchAgents/com.ednewsbot.digest.plist
```

**注意**：檔名就叫 `com.ednewsbot.digest.plist`。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.ednewsbot.digest</string>
  <key>ProgramArguments</key>
  <array><string>/bin/bash</string><string>-lc</string>
    <string>set -a; . /Users/你/ednews/config.env; set +a; /usr/bin/python3 /Users/你/ednews/digest.py</string>
  </array>
  <key>StartCalendarInterval</key><dict><key>Hour</key><integer>8</integer><key>Minute</key><integer>0</integer></dict>
  <key>StandardOutPath</key><string>/Users/你/ednews/digest.log</string>
  <key>StandardErrorPath</key><string>/Users/你/ednews/digest.err</string>
</dict></plist>
```

**請把 `/Users/你/ednews/` 換成你實際的專案路徑。**
例如路徑是 `~/projects/ed-newsbot`，就改成 `/Users/<你的帳號>/projects/ed-newsbot/`（換成你的使用者名稱）。

#### 第二步：載入排程

打開「終端機」（Terminal），輸入：

```bash
launchctl load ~/Library/LaunchAgents/com.ednewsbot.digest.plist
```

若要停用：

```bash
launchctl unload ~/Library/LaunchAgents/com.ednewsbot.digest.plist
```

#### 第三步：確認有在跑

等到明天 08:00 之後，檢查 log 檔：

```bash
cat ~/ednews/digest.log    # 正常輸出
cat ~/ednews/digest.err    # 錯誤訊息（如果有的話）
```

或立刻手動觸發一次測試：

```bash
launchctl start com.ednewsbot.digest
```

### 🔴 兩個常見殺手（必讀）

#### 殺手 1：筆電睡著不跑

launchd 排程在筆電**螢幕蓋下、休眠**時不會觸發。如果你習慣睡前蓋上筆電，早上 08:00 那個時間點有可能完全跳過。

解法：
- 在「系統設定 → 電池 → 電源變壓器選項」，勾選「網路存取時防止睡眠」（或開 Power Nap）
- 或接上電源後，執行 `caffeinate -i &` 讓系統保持清醒
- 或改用不需要電腦開著的方案（GitHub Actions，見下方）

#### 殺手 2：Google Drive 資料夾讀取權限

若 `digest.py` 的存檔路徑在 `~/Library/CloudStorage/...`（這是 Google Drive 桌面同步的掛載位置），macOS 的安全機制會擋住背景程式的存取。

解法（只需做一次）：
1. 開「系統設定」→「隱私權與安全性」→「完整取用磁碟（Full Disk Access）」
2. 點 `+` 號，加入你的 Python 執行檔（通常在 `/usr/bin/python3` 或 `/usr/local/bin/python3`）
3. 重新載入 launchd plist

## 三、GitHub Actions（雲端、免費）

### 適用情境
- 不想靠本機電腦、希望雲端持續跑
- 可以接受偶爾延遲或跳過
- 願意另外設定 Google Drive API 來存檔

### 基本設定

在 repo 裡新增 `.github/workflows/daily-digest.yml`：

```yaml
name: 每日急診文獻日報

on:
  schedule:
    - cron: '0 0 * * *'   # UTC 00:00 = 台灣時間 08:00

jobs:
  run-digest:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: '3.11'
      # 本 kit 零第三方依賴（純標準函式庫），不需要 pip install
      - name: 執行 digest
        env:
          LINE_CHANNEL_ACCESS_TOKEN: ${{ secrets.LINE_CHANNEL_ACCESS_TOKEN }}
          DIGEST_TARGET_USER_ID: ${{ secrets.DIGEST_TARGET_USER_ID }}
          DEDUP_DIR: /tmp/dedup          # 雲端沙箱每次重置，見下方「存檔問題」
          ARCHIVE_DIR: ''               # 雲端環境沒有 Drive 同步，留空不存檔；需存檔請參考下方選項
          AI_PROVIDER: ${{ secrets.AI_PROVIDER }}        # none | claude | openai；可直接寫 none
          AI_API_KEY: ${{ secrets.AI_API_KEY }}          # AI_PROVIDER=none 時留空即可
        run: python A-每日日報/digest.py
```

> **Secrets 設定位置**：repo → Settings → Secrets and variables → Actions → New repository secret。至少要設 `LINE_CHANNEL_ACCESS_TOKEN` 與 `DIGEST_TARGET_USER_ID`；不用 AI 摘要時 `AI_PROVIDER` 可以直接在 YAML 裡寫死 `none`，不必設成 secret。

### 🔴 GitHub Actions 的坑

1. **存檔問題**：GitHub Actions 的執行環境（沙箱）每次重啟都是全新的，去重狀態資料夾（`DEDUP_DIR`）每次跑完就消失。這代表**每天都會重新送出相同論文**，除非你把去重資料夾的內容持久化到外部：
   - 選項 A：推回 repo（`git push`），但會產生大量提交記錄，且需要 write 權限
   - 選項 B：存到 **Google Drive API**（需要設定 Service Account 或 OAuth2，有一定學習成本）
   - 選項 C：存到 **GitHub Gist** 或其他持久化存儲

2. **排程不準時**：GitHub Actions 的 cron 在尖峰時段可能延遲 **20–40 分鐘**，偶爾甚至整次跳過（GitHub 官方文件有說明）。如果你需要準時 08:00 推送，GitHub Actions 不是最可靠的選擇。

3. **POST 請求**：預設情況下 GitHub Actions 可以對外發出 POST，不需要額外設定。這一點比 Codex Automations 友善。

## 四、Codex Automations（本機 AI 整合）

### 適用情境
- 使用 Codex 桌面 App，且想在同一個環境跑排程
- 願意手動確認網路放行設定

### 本機限制（四個都要注意）

| 限制 | 說明 |
|------|------|
| **電腦要開著** | 和 launchd 一樣，電腦關機或睡眠就不跑 |
| **App 要開著** | Codex App 必須在背景執行中，才能觸發 Automation |
| **專案檔要在** | 腳本路徑必須存在，不能是遠端或暫時掛載的路徑 |
| **防止睡眠** | 需要開啟「Prevent Sleep」，否則排程時間一到電腦已睡著 |

### 🔴 網路 Allowlist 是最常踩到的坑

Codex Automations 預設有網路沙箱，需要手動把允許的網域加進白名單。

你需要放行的兩個網域：

```
eutils.ncbi.nlm.nih.gov
api.line.me
```

**重要**：光放行網域還不夠。Codex 預設很多規則只允許 `GET` 請求。`digest.py` 呼叫 LINE Messaging API push 時使用的是 **POST**，必須明確設定 **允許 POST**，否則推送會靜默失敗（不會報錯，但 LINE 收不到訊息）。

設定位置：Codex → 該 Automation 的「Network Settings」→ 加入上方兩個網域，方法改為 `GET + POST`（或 `Any`）。

### 存檔路徑

Codex 的 Automation 執行環境有沙箱限制，去重資料夾（`DEDUP_DIR`）與存檔資料夾（`ARCHIVE_DIR`）都必須**明確指向沙箱外的固定絕對路徑**，例如：

```
DEDUP_DIR=/Users/你/ednews/dedup
ARCHIVE_DIR=/Users/你/ednews/archive
```

不能用相對路徑（例如 `./dedup`），因為執行時的工作目錄不一定是你以為的那個位置。

## 五、相容性對照表

| 功能 | Claude Routines | Codex Automations | Mac launchd | GitHub Actions |
|------|:--------------:|:-----------------:|:-----------:|:--------------:|
| **定時排程** | ✅ 雲端 cron | ✅ 本機觸發 | ✅ 本機觸發 | ✅ 雲端 cron（可能延遲） |
| **雲端常開**（不需電腦開著） | ✅ | ❌ 需電腦 + App 開著 | ❌ 需電腦開著 | ✅ |
| **可對外發 POST 請求** | ✅ | ⚠️ 需手動放行且指定 POST | ✅ | ✅ |
| **跨次持久存檔** | ⚠️ 需另外設定 | ✅ 可指沙箱外路徑 | ✅ 本機直接寫檔 | ❌ 沙箱每次重置（需額外設定） |
| **可執行本地 LLM / API 呼叫** | ✅（雲端 Claude） | ✅（本機任意 API） | ✅（本機任意 API） | ✅（需 secret 設定 API key） |

> **推薦組合**：
> - **最省事、本機跑**：Mac launchd + 本機存檔 → 注意睡眠和 Drive 權限兩個坑
> - **完全雲端**：GitHub Actions + 存 Gist 或 Drive API → 接受延遲、需要設定存檔
> - **Codex 用戶**：Codex Automations → 記得手動設 POST 放行

## 補充：如何確認 launchd 有順利載入

```bash
# 查看目前已載入的 agents 中有沒有你的
launchctl list | grep ednewsbot

# 輸出範例（第一欄是 PID，- 代表沒在執行中，等待下次排程）
-   0   com.ednewsbot.digest
```

若顯示 `0`（exit code 0）代表上次執行成功；若顯示其他數字，去查 `digest.err` 看錯誤原因。
